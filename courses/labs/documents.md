# documents 实验手册

来源快照：`documents@26.715.12143`（2026-07-20）。所有练习仅使用合成 fixture 和只读判断。
合成 fixture 约定：`<synthetic-fixture>` 是占位符，不是本机文件；每节至少替换为一段虚构项目备忘录文字、一个标签文件名（如 `demo-outline.docx`）和目标交付面。练习只检查路由、结构与验收清单，不创建或上传文档。
本手册中的“输出/成品/链接”均指提示词中应列出的预期结构与验收证据，不实际创建、上传、部署、发送或改变外部状态。
建议用时：每个单元 10–15 分钟。

## DO01 Documents 插件总览

### 1. 用途

把以 Word、DOCX、Google Docs、memo、报告或可编辑文稿为最终产物的请求路由到 Documents skill。

### 2. 适用与不适用场景

- 适用：用户要创建、编辑、审阅、修订、批注或交付 Word、DOCX 或 Google Docs 文档。
- 不适用：最终产物是 PDF、电子表格或普通聊天答复，且不需要可编辑文档。

### 3. 输入/输出

- 输入：写作目标、内容、目标文件类型、现有 DOCX 或模板和交付要求。
- 输出：明确的 Documents skill 路由、需要的源文件和最终文档交付面。

### 4. 最小调用模板

```text
@documents
请使用 @documents（Documents 插件总览；skill slug: 插件入口）。
任务：基于下方合成材料，把以 Word、DOCX、Google Docs、memo、报告或可编辑文稿为最终产物的请求路由到 Documents skill。
材料：<synthetic-fixture>
```

### 5. 边界与风险

插件入口只负责文件类型路由；文档质量要由 Documents 的 render-and-verify 流程证明。课程练习不得读取真实客户数据、凭据或生产状态，也不得发送、部署或写入外部系统。

### 6. 提示词练习

```text
@documents
这是一个完全虚构的文件练习：<synthetic-fixture>。
请先判断是否适用，再输出明确的 Documents skill 路由、需要的源文件和最终文档交付面。
不要把 PDF 或工作簿任务误路由为 DOCX，或未验证便声称文档完成。
```

## DO02 Documents:文档处理

### 1. 用途

使用工作区提供的依赖创建或局部编辑 DOCX，并通过逐页 PNG 渲染检查后交付。

### 2. 适用与不适用场景

- 适用：任务需要创建、修改、修订、批注、检查或导出 Word、DOCX 或 Google Docs 目标文档。
- 不适用：用户只要求从 PDF 提取内容，或最终产物是电子表格。

### 3. 输入/输出

- 输入：内容要求、目标 DOCX、可选模板、文档类型、样式约束和目标交付面。
- 输出：DOCX 结构检查和逐页视觉 QA 的执行方案、预期证据字段及交付清单（练习不创建或导入文档）。
- 前置依赖：真实执行需 loader 提供的文档运行时与可用渲染器；课程不创建 DOCX。

### 4. 最小调用模板

```text
@documents
请使用 $documents:documents（Documents:文档处理；skill slug: documents）。
任务：基于下方合成材料，写出使用工作区依赖创建或局部编辑 DOCX、再逐页 PNG 渲染检查的方案；只列预期证据，不创建或交付文件。
材料：<synthetic-fixture>
```

### 5. 边界与风险

必须使用 loader 返回的依赖；每批有意义的编辑后都要重新渲染并检查，缺少 LibreOffice 时才可披露后跳过视觉门槛。课程练习不得读取真实客户数据、凭据或生产状态，也不得发送、部署或写入外部系统。
