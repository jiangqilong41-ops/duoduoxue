# fastapi1 项目 Skills 实验手册

本手册只观察 `fastapi1@710807b32a2a7af6b48496390d15c728a8afd06b` 的 Git 跟踪材料，快照日期为 2026-07-20。每个单元建议 10–15 分钟。

`<SYNTHETIC_TASK>` 表示完全虚构的任务描述，不是文件、账号、客户记录或运行态。显式 `$skill` 只写在练习提示词中；课程不实际调用 skill、工具、VM、远程服务器、GitHub 或生产服务，也不读取 `.env`、数据库、日志、凭证和客户数据。

## FS01 fastapi1 项目 Skills

### 1. 用途

建议用时：10–15 分钟。

建立 8 个项目 skill 的路由地图：区分源文档、前端、安全、性能、Harness、Git、Windows VM 与远程服务器工作流。

### 2. 适用与不适用场景

- 适用：任务还未确定主 skill，或跨两个边界需要说明 primary 与 companion。
- 不适用：已经明确落到某个 skill，或用户要求课程直接执行 Git、VM、生产或业务动作。

### 3. 输入/输出

- 输入：一个完全虚构的任务、目标代码表面、风险等级与预期交付。
- 输出：一个主要 skill、必要时一个安全 companion、排除理由、所需证据和停止条件。

### 4. 最小调用模板

```text
场景：<SYNTHETIC_TASK>
请从 8 个 fastapi1 项目 skill 中选择一个主要入口；必要时再选一个 companion。
只输出路由、理由、输入和停止条件，不调用工具或改变状态。
```

### 5. 边界与风险

总览只负责路由，不替代被选中的 skill。Git 发布、VM、远程服务器和真实业务执行都需要独立明确授权。

### 6. 提示词练习

```text
合成场景：一个页面变慢，同时涉及导出权限。
判断主要 skill 与安全 companion，解释为什么不选择 Harness、Git、VM 或远程运维 skill。
```

### 7. 可观察验收清单

- [ ] 能说出 4 个工程 skill 与 4 个工作流 skill 的边界。
- [ ] 路由结果包含主要 skill、可选 companion 与至少一个排除理由。
- [ ] 没有把总览或任何配置文件当成业务执行器。
- [ ] 所有运行态步骤均停在预览。

## FS02 fastapi1:源文档驱动开发

### 1. 用途

建议用时：10–15 分钟。

在外部库、Codex/OpenAI、MCP、FastAPI、Vue 或 ECharts 行为依赖版本时，先查项目事实和一手官方来源。

### 2. 适用与不适用场景

- 适用：框架/API 行为版本敏感、需要可引用依据，或项目实现与官方说明可能冲突。
- 不适用：纯重命名、拼写修复、版本无关的业务逻辑，或用户明确选择速度优先且风险可接受。

### 3. 输入/输出

- 输入：依赖约束或锁定版本、相关项目文件、具体行为问题和候选官方页面。
- 输出：项目事实、官方事实、推断、冲突、引用与未验证项的分栏记录。

### 4. 最小调用模板

```text
$source-driven-development
场景：<SYNTHETIC_TASK>
先从固定 Git 材料识别版本与项目约束，再列出应核对的一手官方页面。
找不到依据时标为“未验证（UNVERIFIED）”；不要实现或联网。
```

### 5. 边界与风险

搜索结果和模型记忆不能充当一手证据；依赖下限不能冒充实际安装版本；官方通用建议也不能静默覆盖仓库 AGENTS 和测试。

### 6. 提示词练习

```text
合成问题：某个 FastAPI 参数在目标版本是否仍推荐？
输出四栏：项目事实、官方来源、冲突、未验证；每个结论说明证据类型。
```

### 7. 可观察验收清单

- [ ] 显式调用 `$source-driven-development`。
- [ ] 先查本地项目事实，再列官方来源。
- [ ] 具体引用优先于首页、搜索摘要或二手文章。
- [ ] 证据不足时停止并保留未验证状态。

## FS03 fastapi1:前端 UI 工程

### 1. 用途

建议用时：10–15 分钟。

在现有 Vue 3 全局版、Tailwind CDN 与 `html/js/` 共享工具架构内设计页面交互、响应式和可访问性改动。

### 2. 适用与不适用场景

- 适用：修改 `html/**` 页面、脚本、图表、认证跳转、布局、键盘交互或视觉质量。
- 不适用：普通后端任务，或未经用户批准要引入 React、Vue SFC、Vite、客户端 store 或整体重设计。

### 3. 输入/输出

- 输入：虚构页面目标、现有页面模式、共享脚本、加载/错误/空状态和四个目标视口。
- 输出：最小改动方案以及键盘、语义、状态、响应式和视觉验证矩阵。

### 4. 最小调用模板

```text
$frontend-ui-engineering
场景：<SYNTHETIC_TASK>
沿用 Vue 3 全局版、Tailwind CDN 与现有共享脚本，给出最小 UI 方案。
只列预期 DOM、状态和验证证据，不修改页面或启动浏览器。
```

### 5. 边界与风险

页面可打开或单张截图都不能证明可访问性和响应式；没有明确批准时不得引入新的前端构建体系。

### 6. 提示词练习

```text

设计 320、768、1024、1440 四个视口的验收矩阵，并指出应复用的共享脚本。
```

### 7. 可观察验收清单

- [ ] 显式调用 `$frontend-ui-engineering`。
- [ ] 方案保留项目现有前端架构。
- [ ] 覆盖键盘、语义、加载、错误、空状态和四视口。
- [ ] 浏览器运行证据明确标为未执行。

## FS04 fastapi1:安全加固

### 1. 用途

建议用时：10–15 分钟。

在鉴权、授权、secrets、外部输入、导出、数据库、Redis、回调或外部集成出现时，审查信任边界与最小权限。

### 2. 适用与不适用场景

- 适用：请求涉及用户身份、对象级权限、敏感数据、输入校验、文件、回调、AI 或第三方服务。
- 不适用：与安全边界无关的纯展示调整；新增认证、CORS、敏感数据类别或外部服务仍需用户明确批准。

### 3. 输入/输出

- 输入：合成 endpoint、角色、资源归属、输入 schema、输出字段和日志/回调路径。
- 输出：威胁、现有控制、证据、缺口、批准门槛与验证计划。

### 4. 最小调用模板

```text
$security-and-hardening
场景：<SYNTHETIC_TASK>
只用虚构字段审查认证授权、输入、输出、日志和外部调用边界。
不要读取或构造真实 token、数据库 URL、客户内容或环境值。
```

### 5. 边界与风险

前端隐藏不是授权；secret 只说明存在与风险而不回显。新增 auth/CORS/外部集成、上传、限流或提权属于 Ask First。

### 6. 提示词练习

```text
合成接口：导出一份按区域限制的数据文件。
列出后端依赖、对象级权限、输入校验、响应字段和日志泄露风险。
```

### 7. 可观察验收清单

- [ ] 显式调用 `$security-and-hardening`。
- [ ] 安全边界落在后端，而非仅靠客户端。
- [ ] 没有出现任何真实 secret 或客户数据。
- [ ] 需批准的设计变化与可只读检查的事项分开。

## FS05 fastapi1:性能优化

### 1. 用途

建议用时：10–15 分钟。

对慢页面、图表、聚合接口、批量查询或性能回归建立“测量—定位—修复—复测—守卫”闭环。

### 2. 适用与不适用场景

- 适用：已有可描述的慢、卡顿、查询成本、Core Web Vitals 或回归症状。
- 不适用：没有可重复症状或基线，却准备先加缓存、任务系统、构建工具或架构层。

### 3. 输入/输出

- 输入：合成流程、数据规模、环境条件、基线指标、单一性能假设和预算。
- 输出：可重复基线、瓶颈证据、最小修复候选、复测与防回归方案。

### 4. 最小调用模板

```text
$performance-optimization
场景：<SYNTHETIC_TASK>
先定义同一流程的基线和瓶颈证据，再给最小优化与复测方案。
不要修改数据库、启动 profiler、访问生产或新增缓存。
```

### 5. 边界与风险

没有测量就不归因；前端指标不能替代 API/SQL 定时。新增缓存、任务系统或构建工具需要证据与用户批准。

### 6. 提示词练习

```text
合成症状：列表 API 的 p95 上升，同时页面 INP 变差。
分别列出后端与前端测量，避免先验地把问题归因于数据库。
```

### 7. 可观察验收清单

- [ ] 显式调用 `$performance-optimization`。
- [ ] 同一流程有可比较的基线与复测字段。
- [ ] 只提出最小、有证据的优化候选。
- [ ] 生产测量和真实数据明确不在练习内。

- 输入：合成变更、适用 AGENTS、相关 config/contract/Hook/Rule/skill 字段和预期 consumer。

## FS07 fastapi1:Git 分支审查合并

### 2. 适用与不适用场景

- 适用：用户明确提出 branch review、PR 发布/更新、merge 或本地分支清理。
- 不适用：普通代码编辑、单纯只读文件审查，或用户未授权任何 GitHub/分支状态变化。

### 3. 输入/输出

- 输入：合成 base/branch 图、工作树状态、diff 摘要、测试结果与 PR 目标。

### 4. 最小调用模板

```text
$git-branch-pr-merge
```

脏工作树归属不明、checks 失败或分支含 main 不可达提交时停止。默认只考虑确认安全的本地分支；远端清理必须另行明确要求。

- 不适用：普通后端/前端工作、生产服务器运维，或需要执行真实客户任务但没有具体授权。

## FS09 fastapi1:远程服务器运维

建议用时：10–15 分钟。

在用户明确要求时规划受控生产 SSH、部署、服务检查、health/ready、readiness 与目标 SHA 回读。

### 2. 适用与不适用场景

- 不适用：本地开发、Windows VM、通用 SSH 教程，或没有具体生产授权的课程练习。

### 3. 输入/输出

- 输入：`<PRODUCTION_HOST>`、`<DEPLOY_DIR>`、`<SERVICE>`、目标 commit、预期健康面和停止条件。
- 输出：脱敏预检、部署顺序、证据矩阵、阻塞条件和恢复路径。

### 4. 最小调用模板

```text
$remote-server-operator
场景：<SYNTHETIC_TASK>
```
