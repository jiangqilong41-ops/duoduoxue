# mattpocock-skills：10–15 分钟技能课程

本手册使用 `mattpocock-skills@1.2.0+codex.9603c1c` 的 `2026-07-20` 本地脱敏快照。所有练习只使用合成材料与只读判断。
本手册中的“输出/成品/链接”均指提示词中应列出的预期结构与验收证据，不实际创建、上传、部署、发送或改变外部状态。


## MP01 插件总览

### 1. 用途

建议用时：10–15 分钟。

建立 `mattpocock-skills@1.2.0+codex.9603c1c` 的技能地图：在真实工程任务中判断需求澄清、研究、规格拆分、TDD、诊断、审查与交接应走哪条工作流。

### 2. 适用与不适用场景

- 适用：需要先判断插件覆盖范围、skill 分工和安全调用方式。
- 不适用：需求已经明确落到一个具体技能时，不要继续停留在路由层。

### 3. 输入/输出

- 输入：插件 manifest、canonical skill 清单、相邻 `agents/openai.yaml` 的显示名与调用策略。
- 输出：能解释总览课与 21 个 skill 单元的对应关系，并为合成场景选出正确入口。

### 4. 最小调用模板

```text
检查插件 mattpocock-skills 的技能地图。只输出候选 skill、选择理由、所需输入和停止条件；不要调用工具、安装依赖或改变外部状态。
```

### 5. 边界与风险

固定使用 `local-sanitized` 的 `1.2.0+codex.9603c1c` 快照；课程示例不读取凭证、客户数据或运行态秘密，也不自动发送、发布、部署或付费。

### 6. 提示词练习

```text
合成场景：一家虚构团队描述了一个与本插件相关的任务。请列出至多两个候选 skill，说明为什么选择或排除；只做路由分析。
```

### 7. 可观察验收清单

- [ ] 能说出插件名、版本与 skill 数量。
- [ ] 知道第一课是总览，后续每个 canonical skill 各占一个单元。
- [ ] 调用记录同时包含插件名、slug 和 display name。
- [ ] 输出只含路由、理由和停止条件，没有真实外部副作用。

### 2. 适用与不适用场景

- 适用：不确定当前工程任务应使用哪个技能或组合流程。
- 不适用：已经明确知道要调用的具体技能。

### 3. 输入/输出

- 输入：任务现状、代码库是否存在、工作规模与期望交付。
- 输出：推荐的技能入口、组合顺序与分支条件。

## MP03 Matt Pocock:双轴代码审查

### 1. 用途

建议用时：10–15 分钟。

分别从仓库规范和原始规格两条轴线并行审查代码变更与遗漏。本单元训练的核心判断是：场景属于“审查相对固定点的分支或 PR，并分别核对仓库规范和原始规格”时选择它。

### 2. 适用与不适用场景

- 适用：审查相对固定点的分支或 PR，并分别核对仓库规范和原始规格。
- 不适用：尚未给出可解析固定点，或用户要求直接修改代码。

### 3. 输入/输出

- 输入：固定点、三点 diff、提交列表、规范文件与规格来源。
- 输出：彼此分开的 Standards 与 Spec 审查结果。

前置依赖：仓库中可核对的问题跟踪器与领域文档约定；首次使用时先完成技能初始化。

### 4. 最小调用模板

```text

```

### 5. 边界与风险

先验证固定点和非空 diff；审查发现不等于已修复。任何真实账户、客户数据、凭证或外部写入都不属于本单元练习。

建议用时：10–15 分钟。

按预先确认的测试接缝执行红绿循环，以纵向切片交付最小实现。本单元训练的核心判断是：场景属于“以红绿循环在预先约定的公共接缝构建行为”时选择它。

### 2. 适用与不适用场景

- 适用：以红绿循环在预先约定的公共接缝构建行为。
- 不适用：用户只要事后补覆盖率，或测试只能绑定实现细节。

### 3. 输入/输出

- 输入：单个可观察行为、公共接口、测试位置与最小运行命令。
- 输出：先失败再通过的行为测试与最小生产实现。

```text

```

### 5. 边界与风险

测试公共行为而非内部结构；每个切片必须亲眼经历红到绿。任何真实账户、客户数据、凭证或外部写入都不属于本单元练习。
