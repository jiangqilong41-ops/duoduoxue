# 三套课程英语术语通俗解释

本表覆盖三套课程学习正文中的技术术语、缩写、产品名、状态名和关键配置名；课号、题号、文件路径、命令参数、示例值及 A/B/C/D 不作为术语收录，重复术语只解释一次。

## 三套课程共用术语

| 术语 | 一句话解释 |
|---|---|
| Agent | 能根据目标自己判断下一步并调用工具完成任务的 AI 助手。 |
| AI | 让计算机表现出理解、推理或生成内容能力的一类技术。 |
| Model | 接收输入并生成判断或回答的 AI 核心。 |
| Harness | 把模型、工具、权限、上下文和运行流程可靠连接起来的宿主程序。 |
| Prompt | 交给模型的任务说明、背景材料和行为规则。 |
| Context | 模型当前一次推理能够看到的全部信息。 |
| Token | 模型读写文本时使用的计量小单位，一个汉字或单词可能占一个或多个 token。 |
| Tool | 供 Agent 读取信息或执行动作的受控能力。 |
| Tool call | 模型按约定名称和参数发出的一次工具调用请求。 |
| Handler | 真正接收请求并执行具体逻辑的处理函数。 |
| API | 让不同程序按约定互相请求功能或数据的接口。 |
| CLI | 在终端里输入命令来操作程序的界面。 |
| UI | 用户能够看见并点击、输入或操作的界面。 |
| ID | 用来唯一识别一次请求、任务或数据记录的编号。 |
| Config / Configuration | 控制程序如何运行的一组设置。 |
| Profile | 一套可切换使用的配置组合。 |
| Schema | 对数据有哪些字段、字段类型和约束的正式说明。 |
| Protocol | 两个系统通信时共同遵守的消息格式和交互规则。 |
| Runtime | 程序真正运行时所处的环境和状态。 |
| Plugin | 安装后给现有程序增加一组能力的扩展包。 |
| Skill | 告诉 Agent 在特定任务中应遵循什么步骤和知识的说明包。 |
| Hook | 在程序运行到某个固定时机时自动触发的扩展入口。 |
| Rules | 用来判断某个操作应该允许、询问还是拒绝的规则集合。 |
| Sandbox | 把程序活动限制在安全范围内的隔离环境。 |
| Permission | 规定某个主体能不能执行某项操作的权限。 |
| Audit | 留下可追查记录，以便知道谁在何时做了什么。 |
| Workflow | 为完成一类任务而按顺序组织起来的一组步骤。 |
| Task | 有明确目标、状态和完成条件的一项工作。 |
| Job | 交给系统在前台、后台或指定时间执行的一次工作。 |
| Worker | 专门从队列或任务系统领取并执行工作的进程。 |
| Client | 主动向服务端发请求的程序。 |
| Server | 接收请求并提供数据或功能的程序。 |
| Request | 客户端发给服务端的一次请求。 |
| Response | 服务端处理请求后返回的结果。 |
| Payload | 请求或消息中真正承载业务数据的部分。 |
| Endpoint | API 中可以被请求的一个具体地址和操作入口。 |
| Middleware | 在请求到达业务代码前后统一执行认证、日志等工作的中间层。 |
| Route / Router | Route 是一个请求入口，Router 是集中登记和分发这些入口的组件。 |
| Callback | 某件事发生后由系统反过来调用的函数或接口。 |
| Async | 发起耗时工作后不原地等待，让程序可以先处理别的事情。 |
| Sync | 当前工作完成后才继续执行下一步的同步方式。 |
| Snapshot | 在某个时间点保存下来、以后可复查的一份状态副本。 |
| Manifest | 列出一个软件包包含什么以及如何加载它的清单文件。 |
| Scope | 一项规则、权限或配置实际生效的范围。 |
| Provider | 为程序提供模型、数据或其他外部能力的服务方。 |
| env | 由运行环境提供给程序的配置值，常用来放不应写进源码的设置。 |
| Ref | 精确指向某个来源版本的引用。 |
| Version | 用来区分软件不同发布内容的版本标识。 |
| Status | 表示任务、服务或数据当前处于什么阶段的状态。 |
| Timeout | 等待超过规定时间后主动停止本次操作。 |
| Retry | 操作失败后按规则再次尝试。 |
| Backoff | 连续重试时逐步延长等待时间，避免把故障系统压得更重。 |
| Heartbeat | 程序定期发出的“我还活着”信号。 |
| Lease | 带有效期的临时占用权，过期后其他执行者可以接手。 |
| Lock | 防止多个执行者同时修改同一份状态的互斥机制。 |
| Cache | 为了下次更快而临时保存的可再生成数据。 |
| Queue | 让任务排队等待 Worker 依次处理的结构。 |
| JSON | 一种用键、值、数组表达结构化数据的文本格式。 |
| TOML | 一种强调可读性的配置文件格式。 |
| YAML / YML | 一种靠缩进表达层级、常用于配置和自动化流程的文本格式。 |
| CSV | 用逗号等分隔符保存表格数据的纯文本格式。 |
| HTML | 描述网页内容结构的标记语言。 |
| CSS | 控制网页颜色、间距和布局等外观的样式语言。 |
| JavaScript | 主要用于网页交互，也能在服务端运行的编程语言。 |
| Markdown | 用简单符号编写标题、列表和链接的轻量文本格式。 |
| Python | 语法较直白、常用于后端、自动化和数据处理的编程语言。 |
| Bash | macOS 和 Linux 终端中常见的命令解释器。 |
| Command | 用户在终端中输入、让程序执行某项操作的命令。 |
| README | 放在项目中说明用途、安装方式和使用方法的入门文档。 |
| Git | 在本地记录代码历史并支持分支协作的版本控制工具。 |
| GitHub | 托管 Git 仓库并提供评审、自动化和协作功能的平台。 |
| PR | Pull Request 的缩写，表示请求团队审查并合并一组代码改动。 |
| CI | 每次代码变化后自动构建和测试的持续集成流程。 |
| E2E | 从用户入口一直测到后端结果的端到端测试。 |
| diff | 两个版本之间具体增加、删除和修改了什么的差异。 |
| checkout | 在 Git 中切换到某个分支或版本的操作。 |
| HTTP | 浏览器、客户端和服务端传递请求与响应的基础网络协议。 |
| HTTPS | 在 HTTP 外加密通信并校验服务端身份的安全版本。 |
| REST | 用资源地址和 HTTP 方法组织 API 的常见设计方式。 |
| WebSocket | 建立一次长连接后允许客户端和服务端随时双向发消息的协议。 |
| SSE | 服务端通过一条 HTTP 长连接持续向客户端单向推送事件的技术。 |
| CORS | 浏览器用来限制一个网站能否请求另一个来源资源的安全规则。 |
| OAuth | 让用户授权第三方使用部分能力而无需交出密码的授权协议。 |
| Bearer token | 谁拿到谁就能使用的访问令牌，因此必须像密码一样保管。 |
| HMAC | 用共享密钥给消息计算校验值，以证明消息未被篡改且来自可信一方。 |
| SSH | 通过加密连接安全登录远程机器或传输数据的协议。 |
| GET | HTTP 中通常用来读取资源的方法。 |
| POST | HTTP 中通常用来提交数据或触发操作的方法。 |
| Cookie | 网站保存在客户端、请求时会自动带回的小段状态数据。 |
| Header | 请求或响应中描述认证、内容类型等附加信息的头部字段。 |
| URL | 用来标明互联网资源所在位置的地址。 |
| stdout | 程序默认输出普通结果的标准输出通道。 |
| Mac | 苹果公司的个人电脑及其 macOS 运行环境。 |
| Windows | 微软公司的桌面操作系统。 |

## 通用 Agent Harness 课程术语

| 术语 | 一句话解释 |
|---|---|
| Agent loop | 模型提出工具调用、系统执行并回填结果、模型继续判断直到给出最终答复的循环。 |
| assistant | 消息记录中代表模型一方发言或工具请求的角色。 |
| history | 按时间保存用户消息、模型请求和工具结果的会话记录。 |
| final response | 模型不再请求工具时交给用户的最终答复。 |
| Registry | 用名称集中登记工具或处理器、供系统查找和分发的表。 |
| map | 用键快速找到对应值的映射结构，本课程中常用于名称到处理器的分发。 |
| Tool pool | 当前 Agent 真正可以发现和调用的工具集合。 |
| allow | 权限系统判定本次操作可以直接执行。 |
| ask | 权限系统判定必须先向用户确认再决定是否执行。 |
| deny | 权限系统判定本次操作不得执行。 |
| block | 系统在执行前拦下一个不符合边界的操作。 |
| trusted | 表示某个来源被明确纳入信任范围，但名字里写 trusted 并不会自动获得权限。 |
| Permission pipeline | 从参数规范化、规则判断、用户确认到实际执行的一整条权限处理链。 |
| audit event | 为日后追查而记录的一次操作事件。 |
| post event | 工具真实执行完成后触发的事件。 |
| unknown-tool | 请求的工具名不在当前工具池中时返回的错误状态。 |
| invalid-args | 工具参数整体格式不符合契约时返回的错误状态。 |
| missing | 工具调用缺少必填参数时返回的错误状态。 |
| extra | 工具调用带了契约未声明的多余参数时返回的错误状态。 |
| wrong-type | 参数值的数据类型与工具契约不一致时返回的错误状态。 |
| handler-error | 工具处理函数运行失败但错误已被统一封装的状态。 |
| RuntimeError | Python 中表示程序运行过程中发生一般性错误的异常类型。 |
| Plan | 当前会话里帮助 Agent 排列步骤和进度的临时工作清单。 |
| owner | 当前负责某项任务的 Agent 或执行者。 |
| pending | 任务已经创建但还没有开始处理。 |
| in_progress | 任务已经被领取并正在处理。 |
| completed | 任务已经达到完成条件。 |
| ready | 任务的前置依赖已满足，现在可以被领取。 |
| claim | 执行者以互斥方式领取一项任务。 |
| Dependency | 一项任务开始前必须先完成的另一项任务或条件。 |
| Skill discovery | 先查看有哪些 Skill 可用、但暂时不读取全部正文的发现过程。 |
| Skill loading | 任务真正需要某个 Skill 时再读取其完整说明的加载过程。 |
| Subagent | 由主 Agent 派出、在相对独立上下文中完成子任务的另一个 Agent。 |
| Parent / Child | Parent 是派发任务的一方，Child 是接收并执行子任务的一方。 |
| Isolation | 把不同 Agent 的消息、权限或工作状态隔开，避免彼此意外污染。 |
| Parallel | 多项互不依赖的工作在同一时间段分别执行。 |
| Context compaction | 把较旧的上下文压缩成更短摘要，以腾出模型可用空间。 |
| Memory | 跨任务保存、以后在相关场景中再取用的长期信息。 |
| System prompt | 优先级较高、用来规定模型身份和基本行为边界的提示。 |
| team_mode | 表示当前是否启用多 Agent 团队协作的运行状态。 |
| context_overflow | 输入内容超过模型本轮可处理的上下文上限。 |
| recoverable | 表示错误满足明确条件后可以尝试恢复。 |
| fatal | 表示错误无法在当前流程中安全恢复，应停止继续执行。 |
| exhausted | 表示允许的重试或恢复次数已经用完。 |
| recovered | 表示系统执行恢复动作后已经重新正常运行。 |
| Background task | 不阻塞当前对话、在后台继续执行的任务。 |
| Scheduler | 根据时间或条件决定何时启动任务的调度器。 |
| Cron | 用固定时间表达式周期性启动任务的传统调度方式。 |
| tick | 调度器进行一次时间检查并触发到期任务的时刻。 |
| MCP | Model Context Protocol 的缩写，是让模型客户端按统一方式连接外部工具和数据的协议。 |
| MCP server | 通过 MCP 向客户端提供工具、资源或提示的服务程序。 |
| Normalization | 把不同写法转换成统一形式，便于比较、查找和校验。 |
| Name collision | 两个不同名称规范化后变成同一个名称而产生的冲突。 |
| Worktree | Git 为同一仓库同时提供另一份独立工作目录的功能。 |
